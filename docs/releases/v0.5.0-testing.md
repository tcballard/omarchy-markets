# Markets v0.5.0 — XPS candidate and acceptance

Status: prepared for testing, not a published release. The release branch adds
quote precision, index units, freshness and session-label corrections to the
watchlist/chart features merged through PR #13, plus candidate packaging.

## Get the exact candidate

Open the preparation PR's successful **Test** workflow run. Download
`markets-candidate-<full SHA>`, unzip it into a new directory and run:

```bash
sha256sum -c SHA256SUMS
```

Read `source.commit` in `RELEASE-MANIFEST.json`; it must match the run's commit
and the artifact name. For PR runs this is GitHub's tested merge commit, not
necessarily the branch-head SHA. Extract `omarchy-markets-0.5.0.tar.gz` into a
new directory. This is the complete source plugin; there is no native binary to
compile. Do not overlay it onto an existing checkout or discard local edits.

Have the local desktop session install that exact candidate into the existing
registered Markets location after backing up its source and widget settings.
Stop if the installation is modified or its ownership is unclear. Preserve
the plugin ID, permissions and bar placement. Validate the candidate with
`omarchy plugin validate <candidate-directory>` before loading it. Record the
archive's SHA-256 and source commit, then restart the shell.

Normal `omarchy plugin update` follows main and will not install this branch.
An ordinary main update is suitable only once the preparation PR is merged and
its exact main candidate is recorded. Avoid an automatic update during the test.

## Focused feature pass

1. **Upgrade:** with the v0.4.0 configuration saved, check symbols, order, pin,
   chart range, data consent, refresh and ticker preferences are unchanged.
2. **Lists:** create an empty list and a copy; add and reorder symbols; pin a
   different symbol in each. Rename, switch back, cancel deletion, then confirm
   deletion of a disposable list. Duplicate names and a ninth list are refused.
3. **Sorting:** choose gainers and losers. Refresh while inspecting a symbol;
   selection stays on that symbol. Manage and the ticker keep saved order.
4. **Charts:** hover/click points; use I, Left/Right, Home/End and Escape/Tab.
   Check the price and UTC timestamp, range isolation and focus return. Change
   symbol, list and range while inspecting; no obsolete marker remains.
5. **Persistence and consent:** choose a sort mode and restart
   the shell. The active list and sort preference return, with the watchlist as
   the opening view. With data paused, switch
   lists and verify requests stay paused.
6. **Layout:** light/dark themes, the normal XPS scale, a short viewport and long
   list names. The popup stays within 560 scaled pixels or three quarters of
   the usable screen height. With twelve symbols and eight named lists, every
   quote remains visible in the watchlist without scrolling. Press I or Chart
   to enter the separate chart view; Watchlist or D returns. Check that each
   Manage section and the profile chooser fit, with no scrollbar or hidden controls.
   Check editor controls, keyboard selection and popup dismissal. Capture the
   new list switcher and chart inspection on the actual desktop.
7. **Units and precision:** indices show points in the ticker, rows, detail,
   statistics and inspected chart points. London equities retain pence; tiny
   nonzero prices remain nonzero, with readable labels at the intended scale.
8. **Quote age:** the header labels successful fetch time as **Fetched**. The
   selected quote's own age and price session remain visible with its chart
   hidden. Old active-session quotes are stale even if requests succeed; last
   completed-session closing quotes remain valid while markets are closed.
   Missing quote times are explicitly unavailable. Exercise old/fresh responses
   using a disposable fictional fixture, not edits to live market values.
9. **Session clarity:** pre-market/after-hours status does not imply an
   extended-hours price. The displayed quote is labelled regular-session;
   continuous crypto markets use their own label. Quotes may be delayed.

Also complete the lifecycle rows in [the release guide](../releasing.md): fresh
install/consent, horizontal and vertical bars, offline/helper recovery,
suspend/resume, reload, disable/re-enable and removal. Preserve the normal
desktop configuration around fresh-install/removal exercises. Record
multi-monitor coverage separately; leave it unclaimed if unavailable.

## Rollback

Keep a copy of the pre-test source and the Markets widget's complete settings,
including any named-list library, before installing or editing the candidate.
Record the old source SHA and whether it was v0.4.0 or later main code.

To recover, disable Markets, restore the recorded previous source, validate it
and restore only its saved widget settings through the installed host's settings
mechanism. Do not replace the entire shell configuration after unrelated changes.
Re-enable and restart the shell, then check symbols, pin and consent before
resuming requests. Preserve the new library separately if it contains useful
edits: v0.4.0 only understands the active flat list and cannot switch or maintain
the other named lists. Do not assume edits made after downgrade synchronize
with the newer library when upgrading again.

## Record and promotion

Record the candidate source SHA and archive digest, full Omarchy SHA,
architecture, Qt/Quickshell versions, display/scale, themes, date, each result
and screenshot provenance. Mark failed or unrun checks explicitly. The older
v0.4.0 screenshot and acceptance do not establish v0.5.0 acceptance.

Before publication, attach that evidence to the PR, update the preparation
notices and preview, and verify the final main source. The Release workflow
requires its own exact-main host record. Neither downloading this artifact nor
passing automated CI supplies that record. Do not set host checks to passed
until the required desktop checks actually pass.
